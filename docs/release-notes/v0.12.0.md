v0.12.0 — 编辑器配置、节点本地调用与边界加固

leetcode-local-cli 0.12.0 新增用户级编辑器设置、`ListNode` / `TreeNode` 本地调用自动转换与可定位错误详情，并加固提交区域解析、GraphQL 错误识别、DevTools 登录超时预算和发布产物门禁。本项目仍处于内测阶段，不提供跨大版本的静默配置降级或旧状态迁移。

## 用户体验

- 新增 `lc config editor`：支持预设 `zed`、`code` / `vscode` 以及可执行文件绝对路径，支持可重复的 `--arg` 参数数组与 `--clear` 清除。用户配置独立于工作区保存，可在 `init` 前设置并在初始化或切换工作区后保留。
- `lc solve` 按 `--no-open` > `--editor` > 用户配置 解析编辑器（临时 `--editor` 不继承旧参数）；未配置时仅保存并提示，禁用系统 `.py` 文件关联与 Windows 非 `code.cmd` 批处理回退。生效的非法 `--editor` CLI 传参返回用法错误退出码 2，损坏的本地编辑器配置仍返回运行错误退出码 1；保存成功但打开失败只警告并退出 0。
- `lc test` 支持按入口 `ListNode`、`TreeNode`、`Optional[...]`、`... | None` 及对应字符串注解进行节点数组转换（兼容 `from __future__ import annotations`、`Literal` 取值与 `Annotated` 元数据边界），支持 `null` / `None`、树尾冗余空位裁剪及原地修改节点参数展示。第一版限定整数无环单链表与普通二叉树，单次输入/输出上限为 100,000 项/节点，辅助节点定义嵌入提交区域外。
- 本地运行异常默认展示类型、原因与可定位的 `solution.py` 行号；`lc test --verbose` 附带不采集局部变量的完整调用栈，`--stdin` 模式通过 JSON Lines 的 `error_line` 和 `traceback` 字段返回。某组超时后的 worker 重启加载失败会保留对应诊断，不中断后续输入。
- `lc check <Submission ID>` 保持单次查询与提交 ID 显示；当接口返回未完成的中间状态（`PENDING` / `STARTED`，对处理中、跨账号不可见或不存在的提交均可能返回该状态）时，改为提示“暂未取得可确认的判题结果”，提醒确认提交 ID 和当前账号，避免误导为必然仍在判题，同时保持 `lc submit` 提交后自动轮询继续等待的既有行为。
- 题目命令（`show`/`get`/`solve`）仅校验本地 `session.json` 格式而不预先在线验证登录态，公开题目查询成功不代表远端登录有效；请通过 `lc status`、`lc profile` 或 `lc doctor` 确认远端登录状态及当前 Cookie 实际对应的账号。
- `lc login` 回退手动 Cookie 时要求交互式终端；在管道或无 TTY 环境下立即提示并以退出码 1 结束（不阻塞等待控制台、不从管道读取明文凭据、不破坏已有 `session.json`），交互下输入 `EOF` 亦干净返回退出码 1。

## 安全与正确性

- 用户配置写入版本独立升级为 v2，工作区 marker 保持 v1、Session 不变；已有 v1 用户配置仍可只读使用，仅在显式设置/清除编辑器或执行 `init` 时写入 v2，防止旧版误判损坏并覆盖新字段。序列化前校验 UTF-8、TOML 可解析性与结构并转义 DEL 控制字符，原子替换失败保留原件。
- `solution.py` 提交区域改用 `tokenize` 词法扫描识别提交区域前头部的 `# @lc` 元数据与独立边界标记，跟踪 `fstring_depth` 忽略嵌套 f-string 内注释与字符串字面量，拒绝缺失、重复、逆序标记以及未闭合字符串/f-string，保留既有语法检查策略且不自动修改用户文件。
- GraphQL 与 REST 请求进一步区分 HTTP `401`（认证失效，提示重新执行 `lc login`）、HTTP `403`（权限拒绝，提示检查当前账号权限或登录状态）以及已确认的结构化 GraphQL 鉴权/权限错误码（`extensions.code` 为 `UNAUTHENTICATED`、`FORBIDDEN` / `PERMISSION_DENIED`），继续拒绝非空 `errors` 响应且不输出原始服务端响应，也保持初始提交 POST 绝不自动重试的策略；题目详情校验必需题目标识字段，缺少 Python3 模板时允许 `lc get` 查看但阻止 `lc solve` 生成 `solution.py`。
- DevTools 浏览器自动登录在单次浏览器尝试内共用 180 秒单调时钟 `deadline`，覆盖首次握手、打开浏览器授权页后的剩余预算重算、窗体就绪延迟、重试与 Cookie 轮询，保持 `Chrome → Edge → 手动 Cookie` 的逐浏览器独立预算，明确 WebSocket `close_timeout` 与 10 秒在线 `user_status` 校验不在轮询硬上限内。
- 发布工作流 `release.yml` 在三平台前置验收阶段增加 wheel 与 sdist 隔离安装 `scripts/smoke_test.py` 验证，覆盖入口、编辑器设置、初始化和节点数组调用。

## 升级说明

```shell
uv tool upgrade leetcode-local-cli
lc --version
```

- 已有 v1 用户配置可继续读取使用；执行 `lc config editor ...` 或 `lc init` 时将自动以 v2 格式保存，升级后请勿再以旧版 `init --repair` 降级配置。
- 如从 `v0.10.x` 或更早版本跨越升级，仍请执行 `lc login` 与 `lc init <原工作区完整路径> --yes`（已有普通 `solution.py` 会保留）。
- Session 仍以明文保存于平台用户状态目录的 `session.json`，本地 worker 不是安全沙箱，请仅在可信工作区运行代码并禁止提交凭据或 `.leetcode_local_cli/workspace.toml`。
